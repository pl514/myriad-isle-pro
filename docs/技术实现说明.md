# 原生跨应用拖拽导出：技术实现说明

## 1. 目标与约束

需求是「把胶囊里的图片像微信发图那样拖到任意软件窗口」。约束有两条：

1. 必须调用操作系统原生 Drag-Drop，不允许用 `mouse_event` / `SendInput` 模拟鼠标拖动；
2. 拖拽数据必须跨进程，且同时满足「按文件接收」和「按位图接收」两类目标。

因此实现完全绕开 WPF 自带的 `DragDrop.DoDragDrop` 包装层，直接调用
`ole32!DoDragDrop`，并自己实现 COM 的 `IDataObject` 与 `IDropSource`。这样：

- 目标窗口由 Windows 的 OLE 拖放循环负责命中、反馈、跨进程封送；
- 数据格式、位图字节、文件路径 (HGLOBAL) 都由我们完全控制；
- 可以获得目标窗口允许的 `dwEffect`，用来做「可放置」高亮。

## 2. 模块与职责

```
IslandWindow.cs
  ├─ AttachCapsuleGestures()   胶囊点击 / 拖动移动窗口（DragMove）
  └─ StartImageDrag()          卡片按住拖动 → NativeImageDrag.Run()

NativeImageDrag.cs
  ├─ DragNative                ole32/user32/kernel32 P/Invoke、常量、日志
  ├─ DragPayload               一次拖拽的数据源（文件路径 / DIB / PNG / 效果）
  ├─ DragDataObject            IDataObject：向目标暴露 HGLOBAL 格式
  ├─ FormatEtcEnumerator       IEnumFORMATETC
  ├─ ImageDropSource           IDropSource：结束判定 + 可放置反馈
  ├─ DragPreviewWindow         跟随鼠标的缩略图（分层透明窗口）
  └─ NativeImageDrag.Run()     组装、启动、清理
```

## 3. 原生拖放调用链

```
用户按住卡片移动
  → WPF PreviewMouseMove 超过 SystemParameters.MinimumHorizontalDragDistance
  → NativeImageDrag.Run(path, fullBitmap, previewBitmap)
      → DragPayload.Create          预先构建数据（避免拖拽中再解码/分配失败）
      → DragPreviewWindow.Show      显示缩略图，后台线程每 15ms 跟随光标
      → DragDataObject / ImageDropSource
      → ole32!DoDragDrop(...)       进入系统拖放循环（阻塞到松手/取消）
          → 系统解析光标下的窗口，必要时跨进程封送 IDataObject
          → 目标调用 GetData(CF_HDROP / CF_DIB / PNG ...) 取数据
          → ImageDropSource.GiveFeedback(dwEffect)  → 缩略图高亮
          → ImageDropSource.QueryContinueDrag(...)  → 松手 Drop / Esc Cancel
      → 返回 effect，关闭缩略图
```

`DoDragDrop` 必须在 STA 线程调用；WPF UI 线程本身就是 STA，因此直接在
`MouseMove` 事件里调用是安全的。拖拽期间 OLE 的消息循环会继续泵 WPF 消息，
所以缩略图、动画都能正常刷新。

## 4. IDataObject 细节

### 4.1 格式与内存所有权

- 所有格式都以 `TYMED_HGLOBAL` 提供，内存用 `GlobalAlloc(GMEM_MOVEABLE | GMEM_ZEROINIT)`
  分配，写入时 `GlobalLock`，返回 HGLOBAL 句柄（不是指针）。
- 每次 `GetData` 都重新分配一份，因为接收方取得 `STGMEDIUM` 后拥有所有权；
  `pUnkForRelease` 留空，由 OLE 调 `ReleaseStgMedium` 时 `GlobalFree` 释放。
- `QueryGetData` 校验格式、`DVASPECT_CONTENT`、`TYMED_HGLOBAL`；
  `EnumFormatEtc(DATADIR_GET)` 暴露全部格式；`SetData`/`GetDataHere`/`DAdvise` 返回不支持。
- 注意：`FORMATETC.cfFormat` 是 `short`，注册格式（PNG 等）的最高位为 1，
  必须按 `format & 0xFFFF` 比较，否则会出现「PNG 明明在格式列表里却取不到」的问题
  （开发过程中实际踩过）。

### 4.2 CF_HDROP

布局为 `DROPFILES`（20 字节：`pFiles=20, pt.x, pt.y, fNC=0, fWide=1`）+ UTF-16 路径 +
双 NUL 结尾。目标拿到后可以直接按文件打开/发送。

### 4.3 CF_DIB

`BITMAPINFOHEADER`（40 字节，`biBitCount=24`、`biCompression=BI_RGB`、正高度表示
bottom-up）+ 自底向上的 BGR 行数据（每行 4 字节对齐）。源图先
`FormatConvertedBitmap` 转 `Bgr24` 再 `CopyPixels`。

### 4.4 PNG / image/png

若源文件本身就是 PNG，直接读原始字节（不重新编码，保留原始质量）；
否则用 `PngBitmapEncoder` 从解码后的位图编码。两个格式名指向同一份字节。

### 4.5 Preferred DropEffect

4 字节 `DROPEFFECT_COPY`。可避免资源管理器把拖放理解成「移动」而删除源文件，
同时整体只允许 `DROPEFFECT_COPY`。

## 5. IDropSource 与视觉反馈

- `QueryContinueDrag`：`Esc` → `DRAGDROP_S_CANCEL`；左/右键都松开 →
  `DRAGDROP_S_DROP`；否则 `S_OK` 继续。
- `GiveFeedback(dwEffect)`：`dwEffect != 0` 表示当前目标愿意接收，调用
  `DragPreviewWindow.SetDropAccepted(true)` 把缩略图描边变绿、显示「松开放置」；
  返回 `DRAGDROP_S_USEDEFAULTCURSORS` 保留系统拖拽光标。

## 6. 缩略图窗口

`DragPreviewWindow` 是一个 WPF 分层窗口：

- `AllowsTransparency=true`、无边框、`Topmost`、`ShowActivated=false`；
- 扩展样式 `WS_EX_TRANSPARENT | WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW`，
  保证它既不会抢焦点、也不会成为拖放目标（命中测试穿透）；
- 位置由后台线程每 **4ms** `GetCursorPos`（配合 `timeBeginPeriod(1)` 提升计时器精度），
  位置变化时直接调用 `SetWindowPos(SWP_NOSIZE | SWP_NOZORDER | SWP_NOACTIVATE |
  SWP_ASYNCWINDOWPOS)` 异步移动 HWND，**不再经过 WPF Dispatcher**——这是拖拽时
  缩略图紧跟光标的关键；
- 像素尺寸和虚拟屏幕边界在窗口初始化时一次算好，`MoveTo` 不读任何 WPF 依赖属性，
  因此可以安全地跨线程高频调用；偏移 `+18,+18`，并夹紧到虚拟屏幕内；
- 内容为最多 176×132 的图片缩略图 + 圆角/阴影，目标可接收时叠加绿色描边与提示标签；
- 拖拽结束（成功/取消）都在 `finally` 中关闭，卡片透明度恢复，预览线程退出。

## 7. 手势分离

胶囊窗口本身没有标题栏，所以「点击展开」和「移动窗口」都落在同一个 `Border` 上：

- `MouseLeftButtonDown` 记录起点并捕获鼠标；
- `MouseMove` 位移 < 4px 时什么都不做；
- 位移 ≥ 4px → 标记 `capsuleMoved`、释放捕获、调用 WPF `DragMove()`（系统非客户区拖动）；
- `MouseLeftButtonUp` 时如果没移动过才 `SetExpanded(true)`；
- 移动后的位置写入 `build\data\window.txt`，下次启动校验仍在虚拟屏幕内才恢复。

卡片则只在**面板内部**存在，与胶囊手势不在同一元素上；卡片拖动使用系统阈值
（`SystemParameters.MinimumHorizontalDragDistance/Vertical`），超过后立刻释放鼠标捕获，
再进入 OLE 拖拽循环。两条路径互斥，`dragOut` 标志保证拖拽期间窗口失焦也不会收起。

## 8. 失败处理与诊断

- 缩略图创建失败不会阻断拖拽（`preview` 置空后继续）。
- 数据构建失败（超大图、损坏图片）时直接放弃本次拖拽，UI 恢复原样。
- 所有异常写入 `%TEMP%\IslandShot-drag.log`，包含时间、阶段、effect。
- `%TEMP%\IslandShot-error.log` 仍由 `Program.cs` 记录未处理异常。

## 9. 兼容性期望

| 目标 | 使用的格式 | 预期结果 |
| --- | --- | --- |
| 微信 / 企业微信 | CF_HDROP | 输入框出现图片，按发送 |
| 画图 (mspaint) | CF_DIB（优先）/ CF_HDROP | 画布粘贴位图；按文件打开则新标签页 |
| Chrome / Edge 文件框 | CF_HDROP | 文件框收到图片文件 |
| Word / WPS | CF_HDROP 或 CF_DIB | 插入图片 |
| 资源管理器 / 桌面 | CF_HDROP + Copy 效果 | 复制出一个图片文件 |

> 个别只认 `CF_BITMAP`（非 DIB）的老程序不在支持范围内；主流软件均接受上表格式。

## 10. 完整性级别与拖放失败排查（UIPI）

Windows Vista 之后，拖放受 **UIPI（User Interface Privilege Isolation）** 约束：
**低完整性（Low IL）进程不能把拖放数据交给中完整性（Medium）及更高完整性的窗口**。
被拒绝时系统不会报错，源端只会看到 `DoDragDrop` 返回 `effect=0`，目标窗口甚至不会
调用我们的 `IDataObject::QueryGetData`。

远程桌面/自动化沙箱里，从代理或它的 shell 启动的进程常常是 Low。可用这些现象确认：

- `whoami /groups` 里出现 `Mandatory Label\Low Mandatory Level`；
- `%TEMP%\IslandShot-drag.log` 里 `integrity=Low`（本版每次拖拽/启动都会记录）；
- 拖到同为 Low 的测试探针正常（`effect=1`），拖到微信/资源管理器全为 `effect=0`。

处理方式：

1. 最省事：在**桌面上双击** `启动 万象岛.cmd`（或 `build\MyriadIsle.exe`）。
   资源管理器拉起的就是 Medium，托盘图标和拖到微信都正常，**不需要管理员**。
2. 程序启动时会读自己的完整性级别：
   - Low：弹一个不依赖托盘的说明窗（`src\StartupNoticeWindow.cs`），写明原因和做法；
     窗口里可勾「下次不再提示」（存 `build\data\settings.txt` 的 `LowPrivilegeNotice`）。
   - Medium：正常挂托盘图标；只有拖拽真的被拒时才提示。
3. 以管理员（High）运行也能拖到 Medium 目标（High → Medium 允许），但没必要；
   而且 High 拖 High 需要两边都提权。普通权限最通用。
4. 不要试图用 `ChangeWindowMessageFilter` 绕过：它只放行窗口消息，不改变 OLE
   拖放数据的跨完整性封送，仍会被拒绝。
5. 低权限下托盘图标根本不存在（`Shell_NotifyIcon(NIM_ADD)` 返回 FALSE），
   所以提示不能靠气泡，必须用独立窗口。

> 本机实测（2026-11-04）：同一个 `Shell_NotifyIcon(NIM_ADD)` 调用在 Low 下返回
> `FALSE`、在正常桌面下成功；Low 下拖到微信 `effect=0`，Medium/High 下正常。
