# 音乐面板-交接包

> **一句话**：绿球 → 胶囊里长出一块音乐面板；没登录时是一张平台登录卡，点平台弹独立的
> WebView2 登录窗，登完自动回来，面板切成"已登录"的播放器骨架。
> **这一版只做壳**：歌单还是灰条占位，播放键按不动——不是 bug。

## 3. 交互流程

```
点绿球
  → OpenMusicPanel()
      · 从图片面板进：淡入 + PopIn（不播胶囊形变）
      · 从胶囊进：走正常 SetExpanded(true)，surface 选 musicPanel
      · 没登录 → 登录选择卡盖住主体
点平台卡片
  → OpenMusicLogin(platform)
      · 新窗口贴在面板正上方，加载该平台官方登录页
      · 用户自己扫码 / 输账号（我们不碰验证码、不代登录）
      · 每 1.2 秒查一次 cookie，命中 → LoggedIn 事件 → 关窗
      · 或用户点「我已登录」→ 同一条回调
  → 面板：musicPlatformId = 平台 Id，写 data\music-session.txt，切成"已登录"
点 ←  → BackToImagePanelFromMusic()：窗口不收起，只把内容换回图片面板
点 × / Esc → CloseMusicPanel()：收起回胶囊；下次展开直接回到音乐面板
```

## 4. 登录判据（cookie 名）

登录态不靠页面元素猜，靠 cookie——这几个平台都没有对个人开放的 OAuth，
唯一稳的路子是"用户自己在官方网页登录一次，我们读同一次会话的 cookie"。

| 平台 | 登录页 | cookie 名（命中任一即算登录） |
| --- | --- | --- |
| 网易云音乐 | `music.163.com/#/login` | `MUSIC_U` |
| QQ 音乐 | `y.qq.com/n/ryqq/` | `qm_keyst` / `qqmusic_key` |
| 酷狗音乐 | `www.kugou.com/` | `KuGoo` / `token` |
| 汽水音乐 | `music.douyin.com/` | `sessionid` / `sessionid_ss` |

改名 / 失效时只改 `MusicPlatforms.cs` 一处。cookie 只在进程内用于判断登录，不外发、不写日志。

## 5. 数据落在哪

```
build\data\music-session.txt              上次登录的平台（只有 platform 和 since 两行）
build\data\music\webview2-<平台Id>\        WebView2 的 profile：cookie、缓存、IndexedDB
```

每个平台一个独立 profile，互不串号，和抖音 `data\webview2`、AI `data\webview2-ai\<站点>` 分开。
**要"真的退出登录"得删掉对应 profile 目录**——这一步没做退出按钮，是有意留到接歌单时一起做
（那时才有能力在删 cookie 前复核登录态）。

## 6. 为什么登录必须另开窗口

胶囊窗口是分层透明窗口（`AllowsTransparency = true`），WebView2 是子 HWND：
塞进胶囊里**一点画面都不会显示**（抖音窗、AI 网页版都为此绕开）。所以：

- 面板里的一切必须是原生 WPF（封面、进度条、控制键都是画的）；
- 网页只在独立窗口里出现；
- 面板窗口本身高度定死（`AiPanelHeight + AiPanelTop + 12`），运行时**绝不改窗口 Height**，
  否则分层窗口改尺寸会整块黑屏（见 AI 交接包 §3 方案 B）。

## 7. 下一步：歌单和播放，两条路线

**路线 A：网页驱动（推荐先试）**
登录窗保持活着（隐藏起来），用 `ExecuteScriptAsync` 在官方网页里点列表、读 DOM、点播放键。
- 优点：不逆向签名、不碰版权地址，登录态天然可用；AI 网页版和抖音已经证明这套在项目里跑得通。
- 缺点：依赖页面结构，平台改版会失效；需要在隐藏窗口里持续跑一个网页播放器。

**路线 B：调平台接口**
网易云走 `weapi`（AES + RSA 加密参数），QQ 音乐走 `sign/tk` 签名。
- 优点：数据干净，能直接拿到歌单 JSON 和播放地址。
- 缺点：加密参数要手写且会变；拿到的音频地址有鉴权时效；维护成本高。

建议：先 B 的"歌单列表"只读部分（网易云最容易），播放走 A；两条路都先在网易云上验证，
再决定要不要为 QQ/酷狗/汽水重复一遍。

## 8. 已知限制 / 坑

1. **新增第三块面板时必须补的 4 个守卫**（这次实际踩过）：
   `IslandWindow.cs` 里有一批"AI 面板开着就特事特办"的判断，全是 `aiVisible`，
   加音乐面板时每一处都要带上 `musicVisible`，否则会出怪现象：

   | 位置 | 不补会怎样 |
   | --- | --- |
   | `PreviewMouseLeftButtonUp`（点空白处） | 点面板空白区域把面板收掉 |
   | `Deactivated`（窗口失焦） | 登录窗一抢焦点，面板就没了 |
   | `PreviewMouseWheel`（滚轮） | 音乐面板里滚轮去滚图片卡片 |
   | `MouseHookService` 的 `clickedOutside` | **点登录窗上的任何按钮，身后的音乐面板直接被收起** ← 这次就是这么踩到的 |

   以后再加"第四块面板"，建议先把这几个 `aiVisible` 收敛成一个 `OverlayVisible` 属性，
   不然每加一块面板都要背一遍这张表。
2. 登录窗是 900×800 的固定尺寸：这几个平台的网页版都是桌面布局，460 宽会把扫码框
   挤出可视范围（实测网易云只剩一条横向滚动条）。窗口可以再大，但别比 900 窄。
3. 登录记忆是"上次登过就算已登录"，**不校验 cookie 是否过期**——接歌单时必须用 cookie
   复核一次，复核失败要清 `music-session.txt` 并回到未登录态。
4. QQ 音乐登录页是直接开首页（`y.qq.com/n/ryqq/`），需要用户自己点右上角「登录」；
   如果有更直达的登录地址，改 `MusicPlatforms.cs` 的 `LoginUrl` 即可。
5. `KuGoo` / `token` 是酷狗的常见 cookie 名，命中率没实测过；汽水音乐同理。
   网易云的 `MUSIC_U` 是确定的。
6. 「在浏览器打开」是给网页控件启动失败时留的后路，但浏览器和 WebView2 **不共享登录态**，
   那边登录完必须回来点「我已登录」（否则面板不会切状态）。
7. 现在没有"退出登录"按钮：真要登出得删 `build\data\music\webview2-<平台Id>\`。
   有意留到接歌单时做（那时才有能力先复核再清）。

## 11. 各平台的登录窗（2026-11-06 晚，真机实测）

### 做法：只加载"登录卡"，不加载整站

`MusicLoginWindow` 打开前会做三件事（`AutoOpenLogin`）：

1. 注入脚本把页面上文字含「登录」的最深元素点一下（合成 MouseEvent）；
2. 等 1.6 秒，把页面的浮层结构 dump 到 `data\music\login-dom-<平台>.txt`（选择器靠它找，不靠猜）；
3. 注入 CSS/JS 把外壳藏掉、卡片居中放大。

平台各自的结论：

| 平台 | 登录地址 | 结果 |
| --- | --- | --- |
| 网易云 | 不用窗口 | 面板里原生画二维码（§见上） |
| QQ 音乐 | `graph.qq.com/oauth2.0/authorize?...client_id=100497308&redirect_uri=y.qq.com...` | ✅ 一张干净授权卡；二维码大；登录完跳回 y.qq.com 种 `qm_keyst` |
| 酷狗 | `login-user.kugou.com/login/?appid=1014...` | ✅ 独立扫码页，二维码 150px 左右 |
| 汽水 | `music.douyin.com/` 首页 | ⚠️ "登录/注册"**不认脚本合成点击**（isTrusted=false），真实鼠标点一下就能弹出完整扫码卡 |

QQ 和酷狗的地址都是从 `www.kugou.com` / `y.qq.com` 自己的弹窗 iframe 里 dump 出来的（`login-dom-*.txt`），
不是猜的。这两个地址本身就等于"一张登录卡"，所以窗口可以开小（520 宽）并给一点网页缩放（`MusicPlatform.Zoom`）。

### 汽水为什么点不动

抖音系页面的登录按钮会检查事件 `isTrusted`，`element.click()` 和 `new MouseEvent(...)` 都会被忽略。
两种解法：
- 用 `SendInput` 在按钮的屏幕坐标上发一次真实点击（要先从页面拿 `getBoundingClientRect`，再按窗口位置 + 缩放换算）；
- 或者查 `NewWindowRequested` 的弹窗 URL（还没打日志，下一步加）。

## 12. 歌单导入（2026-11-06 深夜，QQ 音乐，已跑通）

### 结论：qm_keyst 直接能调 QQ 音乐接口，不需要换 sid/vkey

实测在已登录的页面上下文里 fetch u.y.qq.com/cgi-bin/musicu.fcg，只带 qm_keyst cookie 就返回 code:0。
所以不用像 Folia 那样维护一套安卓设备指纹 + 会员会话。

### 三个接口

| 用途 | module / method | 关键参数 |
| --- | --- | --- |
| 全部歌单 | music.musicasset.PlaylistBaseRead / GetPlaylistByUin | uin、encrypt_uin='*' |
| 歌单详情 | music.srfDissInfo.DissInfo / CgiGetDiss | disstid、**dirid（必需，缺了返回 10004）** |
| （反例） | music.srfDissInfo.aiDissInfo / uniform_get_Dissinfo | 实测返回 10006，别用 |

g_tk = hash33(qm_keyst)，算法：h=5381; 每个字符 h += (h<<5)+c; 取 31 位。

### 实现方式

MusicImport.RunApi：开一个 -4000,-4000 的隐藏 WebView2（用平台 profile）→ 打开 y.qq.com →
ExecuteScriptAsync 里 fetch 接口 → window.chrome.webview.postMessage(JSON) 回传 →
C# 用 JavaScriptSerializer 解析。事件驱动，不阻塞界面。

注意：WebView2 的 ExecuteScriptAsync **不会等 Promise**，直接返回 {}。必须用 postMessage 回传。

## 13. 播放（2026-11-07 上午，QQ 音乐，已跑通）

### 链路

```
点歌 → music.vkey.GetVkey / UrlGetVkey（页面上下文 fetch）
      → purl（相对路径！必须补 http://ws.stream.qqmusic.qq.com/）
      → MediaPlayer.Open(url) + Play()
      → 250ms 定时器刷新进度条 / 时间 / 圆点
```

### 踩到的两个坑

1. **purl 是相对路径**：接口返回 `C400xxx.m4a?guid=...&vkey=...`，没有域名。
   直接 `new Uri()` 会抛异常，必须拼上 `http://ws.stream.qqmusic.qq.com/`。
2. **vkey 有时效**（几十分钟），每次播放要重新取，不能缓存复用。

### 已实现

- 播放 / 暂停（按钮图标跟着变）、上一首 / 下一首；
- 进度条 + 时间（0:06 / 3:00）；
- 切歌自动取新地址；播完自动下一首（MediaEnded）；
- 关闭面板后音乐继续播（MediaPlayer 在胶囊进程里）。

### 还没做

- 进度条拖动跳转（seek）、音量滑块可拖（现在固定 70%）；
- 歌词跟随播放高亮/滚动；
- 酷狗 / 汽水 / 网易云的播放地址。

## 14. 歌词点句播放（2026-11-07）

歌词接口返回的 LRC 保留时间轴，解析成 `MusicLyricLine { Time, Text }` 列表，逐行渲染：

## 15. 播放模式 / 队列抽屉 / 列表迷你条（2026-11-07 下午）

### 播放模式（默认随机）

队列面板右上角的小胶囊：随机 → 单曲循环 → 顺序 → 随机（点击循环）。

- 随机：MediaEnded / 下一首 都随机挑一首**能播的**（不会撞到同一首）；
- 单曲循环：MediaEnded 原地重播；
- 顺序：按列表往下，跳过没版权的。

### 自动跳过无版权（修 bug）

之前播到没版权的歌会卡住不动。现在两条路都兜住：

1. `NextMusicSong` 只在 `Playable` 的曲子里找下一个；
2. 取不到 vkey / 取到空地址时 `SkipAfterFailure()` 继续往后，`musicAutoSkip` 最多绕一整圈，防死循环。

### 队列面板改为底部抽屉

原来是右侧竖条 + 大封面，现在改成底部抽屉：抓手条、标题、播放模式胶囊、关闭 ×、列表。
入口也从"海报右下角悬浮圆钮"改成融入底栏的「≡ 队列」胶囊（列表模式在迷你条右侧）。

### 歌曲列表底部迷你条

浏览歌曲时的常驻条：播放/暂停（主色圆钮）、歌名 + 歌手、进度与时间、队列入口。海报模式自动隐藏，避免和底栏重复。

## 16. 歌单/歌曲本地缓存（2026-11-07）

## 20. 投射层：拦截点击 + 跟随封面主色（2026-11-07）

### 颜色跟随封面

Folia 的做法（`Lattice--y_J3DMB.css`）是 `.lattice-chrome { color: inherit }` +
`color-mix(in srgb, currentColor 16%, transparent)`，即整条 chrome 用继承色、随背景变。

我们实现：

1. `ComputeCoverTint(albumMid)`：后台线程下载封面（DecodePixelWidth=32），跳过透明像素求平均色；
2. `Saturate()`：平均色发灰时和音乐主色混 45%，过暗时提亮，保证控制条不发黑；
3. `MusicDesktopLyricsWindow.SetTint(color)`：
   - 控制条背景 = 主色混深（72~84%）的渐变 + 主色淡边；
   - 进度填充 = 主色提亮 55%；
   - 展开卡背景 = 主色混深 86%；
   - 图标行 = 主色淡 15%；
4. 主色按专辑 mid 缓存，切歌才算一次。

## 23. 换账号后二维码不出现（2026-11-08 修）

**现象**：酷狗登错账号 → 点「换平台」→ 选酷狗 → 直接显示"已登录"，二维码不出现；退出登录再选也一样。

## 25. 酷狗歌单导入：结论与暂停（2026-11-08 凌晨）

### 已实现的（保留）

- 酷狗改为**官方扫码登录**（`login-user.kugou.com/v2/qrcode` + `get_userinfo_qrcode`），

- 歌单接口代码在 `src/KugouApi.cs`（签名、请求、解析都写好了，未接线）。

### 卡住的点（证据）

`POST gateway.kugou.com/v7/get_all_list` 无论用哪个 appid（1001/1005/1014）、
数字还是字符串 userid、网页 dfid/kg_mid 还是占位，
都返回 `{"status":0,"error_code":20017}`（appid 1001 时是 20006）。

把 Folia 内嵌的 `kugoumusicapi` 服务**原样跑起来**、喂同一个 token，同样 20017：

```
server running @ http://localhost:3000
{"status":0,"error_code":20017}
```

签名算法已用 node 参考值逐字节验证一致（`fe20a54a923a8ccd64337c3fee2a5e27`），
所以不是签名/参数问题，而是**登录态类型不对**：酷狗网关要求会话先经过
`register_dev`（AES-CBC 加密设备信息 + RSA 包裹密钥，拿 dfid）与设备绑定，
网页扫码/官方扫码接口给的 token 不满足。

### 当前决定（B 方案）

- `StartMusicImport` 白名单只留 `qq`，酷狗进入面板显示「未接导入」，不会再弹失败提示；
- 酷狗**不能放歌**（播放走 QQ 的 vkey，酷狗也没接）；
- 以后要做 A 方案：把 `register_dev` 的 RSA/AES 握手移植到 C#，再打开白名单。

## 26. 酷狗设备注册握手（2026-11-08 上午）

按 kugoumusicapi 的协议移植了 `register_dev`：

1. `key` = 6 位随机串；`encryptKey = MD5(key)[0:16]`、`iv = MD5(key)[16:32]`（UTF-8 字节）；
2. 设备 JSON 用 AES-128-CBC/PKCS7 加密 → base64 作为请求体；
3. `p = RSA_PKCS1v1.5({aes:key, uid, token})`（公钥 DER 自己解析 SPKI，.NET Framework 4.8 没有 ImportSubjectPublicKeyInfo）；
4. `POST userservice.kugou.com/risk/v2/r_register_dev?part=1&platid=1&p=...`（android 签名）；
5. 响应 base64 → 用同一 key/iv 解密 → `data.dfid`；
6. `mid = calculateMid(GUID)`（MD5 十六进制转十进制大整数，用 System.Numerics.BigInteger）。

**踩的坑**：mid 必须在注册**之前**定下来，注册和后续请求用同一个；否则网关仍然拒绝。

**结果**：`register_dev` 成功（拿到了真实 dfid，如 `4WygT31ccNsA1ah4db41VeVM`），
但 `v7/get_all_list` 仍返回 `20017`（appid 1005）/ `20006`（appid 1001）。

**关键证据**：把参考实现 kugoumusicapi 接上同样的 token 跑，也是 20017；给它加上
`X-Real-IP: 127.0.0.1` 后依旧 20017。说明**问题在 token 本身**（官方扫码接口发的 token
不被歌单网关接受），不在请求参数或签名。

下一步若要继续：需要换一种登录方式拿 token（手机号/密码登录 `login_cellphone`，或

### 协议要点（移植到 C# 需要的东西）

1. **扫码登录**
   - `GET https://open.douyin.com/oauth/get_qrcode/?aid=1128&client_key=aw4bbxfujo741d09&scope=…`
     返回 `data.token` + `data.qrcode`（base64 PNG，直接显示）
   - `GET https://open.douyin.com/oauth/check_qrcode/?…&token=&timestamp=` → status: new/scanned/confirmed/expired/refused，confirmed 带 `auth_code`
   - `GET https://open.qishui.com/api/luna/v1/platform/access/code/get/?auth_code=` → access_code
2. **换票据（需 EC 密钥 + CSR）**
   - 生成 P-256 密钥对 + PKCS#10 CSR（CN=bd-ticket-guard）
   - `POST https://open-client.douyin.com/passport/open/get_access_ticket/?aid=1128&client_key=…&device_platform=android`
     body: `access_code` + `open_id`，头：`bd-ticket-guard-version: 1`、`bd-ticket-guard-client-csr: <csr>`
     响应头 `bd-ticket-guard-server-data` → `{ticket, ts_sign, client_cert}`
3. **每个账号请求的授权头**
   - `access-token: <ticket>`
   - `bd-ticket-guard-version: 1`
   - `bd-ticket-guard-client-cert: <client_cert>`
   - `bd-ticket-guard-client-data`: base64(JSON{ts_sign, req_content:"ticket,path,timestamp",
     req_sign: base64(ECDSA-SHA256("ticket=<t>&path=/api/luna/v1/platform<path>&timestamp=<ts>")), timestamp})
4. **公共参数**（每个请求的 query）
   `aid=765213&app_id=765213&app_name=byte_autoservice_lite&version_code=100010&version_name=1.0.10&channel=bydSong&sdk_aid=753999&caller_name=luna_open_sdk&sdk_version_code=100000100&sdk_version_name=0.0.1&sdk_channel=Test&vehicle_type=BYD&device_brand=BYD&device_type=BYD&device_platform=android&resolution=1920x1080&os_version=13&ac=wifi&device_id=&did=&iid=&vehicle_id=qishui-<19位数字>&_timestamp=<秒>&_nonce=<随机>`
5. **接口**（`POST https://open.douyin.com/api/luna/v1/platform<path>`，JSON body + `common_params.user_id`）
   - `/me/info/`、`/me/playlist/`（游标分页）、`/playlist/detail/`、`/media/mget/`、`/search/`、`/feed/mode/`

### 移植工作量

C# 4.8 要自己实现：EC P-256 密钥生成、PKCS#10 CSR 的 DER 编码、.NET 签名(P1363)→DER 转换、guard 头签名。

## 33. 汽水：C# 实现完成（2026-11-08）

### 新增文件

`src/QishuiApi.cs`（约 1200 行）：扫码登录 + EC 密钥/PKCS#10 CSR + 每请求 guard 签名 + 歌单/歌曲/播放/歌词。

会话：`build\data\music\qishui-session.txt`（ticket / guardKey(PKCS#8) / guardCert / guardTsSign / deviceId）
设备号：`build\data\music\qishui-device.txt`（19 位数字，落盘复用）
日志：`build\data\music\qishui.log`（分步：access code → csr → ticket → me/info）

### 登录流程（已在应用内跑通）

1. `GET open.douyin.com/oauth/get_qrcode` → token + 二维码 PNG（直接显示）
2. `GET open.douyin.com/oauth/check_qrcode` → new/scanned/confirmed（confirmed 带 auth_code）
3. `GET open.qishui.com/.../access/code/get` → access_code
4. `POST open-client.douyin.com/passport/open/get_access_ticket`（form：access_code + open_id；
   头：`bd-ticket-guard-version: 1` + `bd-ticket-guard-client-csr: <PEM 整体 base64>`）
   → 响应头 `bd-ticket-guard-server-data`（base64 JSON：ticket / ts_sign / client_cert）
5. `POST open.douyin.com/api/luna/v1/platform/me/info/` 拿 userId（`_000lROH…` 这种字符串）

### 接口与鉴权（关键！）

| 接口 | 鉴权 |
| --- | --- |
| `/me/playlist/`、`/me/info/` | **guard 头**（access-token=ticket + client-cert + 现签 client-data） |
| `/playlist/detail/`、`/media/mget/` | **公共 token**：`access-token: clt.luna.is.number.one`（带 guard 会 28001003 access_token无效） |

guard 签名：`ECDSA-SHA256("ticket=<t>&path=/api/luna/v1/platform<path>&timestamp=<秒>")` → DER → base64，
包进 `bd-ticket-guard-client-data`（JSON 再 base64）：`{ts_sign, req_content:"ticket,path,timestamp", req_sign, timestamp}`。

公共参数（每个请求 query）：aid/app_id 765213、app_name byte_autoservice_lite、version 100010/1.0.10、
channel bydSong、sdk_* 一串、device_brand/type/vehicle BYD、device_id/did/iid=<19位>、vehicle_id=qishui-<19位>、_timestamp、_nonce。

### 踩的坑

1. **`.NET` 的 `EccPublicBlob` 是 CNG `ECS1` 格式**（`"ECS1" + cbKey + X + Y`），不是老的 `BLOBHEADER + cbKey`，
   按老格式读会把 magic 当长度（读出负数）→ CSR 生成抛异常；
2. CSR 的 `bd-ticket-guard-client-csr` 要的是 **PEM 文本整体再 base64**（不是 DER）；
3. `/playlist/detail/` 必须用公共 token（见上表）；
4. 歌曲地址是 `audio/mp4` 且**没有扩展名**，WPF `MediaPlayer` 打不开 → 先下载到
   `%TEMP%\IslandShotMusic\qishui-<id>.m4a` 再播（也当缓存）；
5. 封面是 `urls[0] + uri`，而且**必须带尺寸模板** `~c5_300x300.jpeg`，裸 uri 返回 400；
6. 部分歌只有加密音源（VIP/版权），`GetSongUrl` 返回空 → 走"自动跳过"。
